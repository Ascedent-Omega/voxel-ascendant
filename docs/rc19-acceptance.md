## Continue: spend the existing preparation allowance

coroutine resumes while covered/loading, but `advanceJob` still stopped after
one. The new small scenery steps therefore left most of that allowance idle.
It now consumes up to eight steps or the existing shared 8 ms deadline,
whichever comes first. Foreground play still gets one step, shared across all
probes. `horizon_job_budget_test.lua` verifies these boundaries, including a

## Persistent generated cache investigation (2026-09-28)

- Host src/mods/ImportAccess.lua exposes installation-scoped mod.cache read/write/
  info/exists/delete under mod_cache/<mod-id>, separate from playthrough saves.
  Writes accept byte strings up to 64 MiB per file. SaveData.persistenceFs routes
  storage through the standard or portable root. The standard save-directory
  path is available in the mobile host design; Switch has not been verified.
- This API is infrastructure, not an implemented persistent VASC geometry cache.
  Packaged window scenery assets and session-resident meshes already exist.
  A generated cache should store bounded portable geometry/image data keyed by
  content and renderer version, verify size/integrity, recover from missing or
  partial files, and enforce total disk usage. GPU handles cannot be persisted.
  Disk reads, decoding and GPU uploads still need loading-phase scheduling.
- Such caching targets repeat CPU preparation and loading stalls; it does not
  remove the per-frame cost of geometry, shadows, lights or transparency. Hardware
  performance and thermal behavior require device measurements, not RAM estimates.

- 128 fixed LRU slots, each at most 4 MiB: at most 512 MiB of geometry plus

  Index updates follow data writes; interruption may lose a reusable entry but
  cannot cause a mismatched mesh to be admitted.

## Renderer stability follow-up — 2026-09-28

The remaining stalls were traced per frame, including native allocations,
terrain animation and local lighting. Artifacts are under
`artifacts/vasc-rc19-lookouts/renderer-stability/` in the parent workspace.

- `TerrainAtlas` now stores immutable animation-phase textures. Normal ROM
  water/flower atlases need eight phases, warmed one texture per preparation
  call. Drawing selects an existing texture instead of `replacePixels` on an
  image the GPU may still sample. The bank is limited to 16 images and 4 MiB
  per atlas (at least one image for oversized custom atlases). Oversized custom
  cycles use bounded LRU storage; mobile retains its existing static-atlas path.
  Eviction/invalidation releases every phase and the private CPU scratch copy.
- Water warms the selected SKY/FULL and wireframe shader in the existing
  one-program-per-update preparation lane. Reveal waits for that program or
  its terminal fallback; rejected wireframe programs also warm the ordinary
  fallback. OFF does no compilation.
- Local-light cell selection retains only the strongest required candidates,
  preserving previous ordering and selection exactly. Same-root grid changes
  use a coroutine with a shared 0.75 ms CPU allowance during play / 4 ms under
  cover, checking every eight emitters. The last complete grid remains live
  until indices, light data and visibility can be published together. Root
  changes remain synchronous to avoid applying coordinates from another map.
  GPU publication and a single eight-emitter batch are not hard real-time
  bounded. OFF/reset cancels pending work.
- Pending light jobs reuse their source snapshot. Update-time preparation
  does not resubmit a broader neighborhood over the renderer's pending union;
  a completed render records the actual lighting receipt. This avoids the
  repeated preparation/render replacement seen during the first prototype.
  Reveal also waits for an outstanding grid job to finish.
